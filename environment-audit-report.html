2.2 实际读取的是哪个 .env 文件?

后端 PyCharm 启动时：读取 backend/.env

config.py 中配置为 env_file=".env"（相对路径），Pydantic Settings 从当前工作目录查找。PyCharm 默认将工作目录设为项目根目录或 backend 目录：

  • 工作目录 = backend/ → 读取 backend/.env ✓ 正确
  • 工作目录 = c:\ui-automation\ → 读取 c:\ui-automation\.env（Docker配置） ✗ 错误

关键风险: 如果 PyCharm Run Configuration 的工作目录不是 backend/，会错误读取根目录 .env（Docker 专用配置），导致 DB_HOST=mysql 等容器内地址无法连接。

2.4 加载顺序与优先级

Pydantic Settings 优先级（从高到低）：

  1. OS 环境变量 — os.environ 中已存在的值（最高优先级）
  2. .env 文件 — 通过 env_file=".env" 加载的文件
  3. 代码默认值 — Field(default=...) 中指定的默认值（最低）

注意：Pydantic Settings 读取 .env 文件后，不会将值写入 os.environ。因此代码中直接使用 os.getenv() 的地方（如 alembic/env.py、milvus_client.py、embedding/factory.py）无法读取到 .env 中的值。

3.2 MinIO 配置详情

MinIO 在 docker-compose.yml 中未映射端口到宿主机，仅在 Docker 网络内部通信（供 Milvus 使用）。

# docker-compose.yml 中的 MinIO 配置
minio:
  image: minio/minio:RELEASE.2023-03-24T21-41-23Z
  container_name: test_auto_minio
  environment:
    MINIO_ACCESS_KEY: minioadmin
    MINIO_SECRET_KEY: minioadmin
  command: minio server /minio_data --console-address ":9001"
  # 注意：没有 ports 映射！

结论：MinIO 仅作为 Milvus 的对象存储后端，后端代码不直接连接 MinIO。当前配置正确，无需映射端口。

3.3 根目录 .env 的 DB_PORT 问题

严重：根目录 .env 中 DB_PORT=3307 与 DB_HOST=mysql 冲突

根目录 .env 中配置为 DB_HOST=mysql（容器名）但 DB_PORT=3307（宿主机映射端口）。MySQL 容器内部监听 3306，从容器网络访问应使用 3306。

docker-compose.yml 的 backend 服务通过 environment 覆盖了 DB_HOST=mysql，但没有覆盖 DB_PORT，导致容器内后端尝试连接 mysql:3307（不存在），而非 mysql:3306。

位置: c:\ui-automation\.env 第 13 行 影响: Docker 模式下后端无法连接 MySQL

4.3 alembic.ini 硬编码问题

alembic.ini 第 6 行硬编码了数据库连接字符串：

sqlalchemy.url = mysql+pymysql://root:magic1212@localhost:3306/test_automation?charset=utf8mb4

虽然 alembic/env.py 会通过 _build_database_url() 覆盖此值，但该函数使用 os.getenv() 读取环境变量。在 PyCharm 本地运行时，如果未通过 load_dotenv() 加载 .env，os.getenv("DB_PORT") 返回默认值 "3306"，导致 Alembic 迁移连接到错误的端口。

五、第三方服务配置

5.1 DeepSeek API

Key 读取方式: settings.DEEPSEEK_API_KEY → 通过 Pydantic Settings 从 .env 加载

当前值: 空字符串（DEEPSEEK_API_KEY=）

Mock 逻辑: DeepSeekProvider 的 _is_configured() 检查 bool(self.config.api_key)，空值返回 False，Provider 被标记为 disabled。LLM Gateway 的 fallback chain 会自动跳过 disabled 的 Provider，降级到下一个（Ollama → Mock）。

结论: ✓ 配置正确，无 Mock 残留逻辑。空 Key 时优雅降级。

5.2 Embedding 服务

API 配置: 使用 DashScope text-embedding-v3，与通义千问 LLM 共用 QWEN_API_KEY

API URL: https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings（硬编码在 dashscope_embedding.py）

Provider 选择逻辑:

# embedding/factory.py
self._provider = os.getenv("EMBEDDING_PROVIDER", "dashscope").lower()

问题: 使用 os.getenv() 而非 settings.EMBEDDING_PROVIDER。由于 Pydantic 不写入 os.environ，此处实际始终返回默认值 "dashscope"。虽然结果正确，但如果用户想切换为 "mock"，在 .env 中设置不会生效。

降级机制: 如果 QWEN_API_KEY 为空，can_handle() 返回 False，自动降级到 MockEmbedding（返回零向量）。

5.3 Playwright

使用方式: execution_agent.py 通过 subprocess.Popen 执行 Python 脚本，脚本内部使用 sync_playwright().start() 和 pw.chromium.launch(headless=True)

浏览器路径:

# execution_agent.py 第 117 行
env["PLAYWRIGHT_BROWSERS_PATH"] = os.environ.get("PLAYWRIGHT_BROWSERS_PATH", "")

当 PLAYWRIGHT_BROWSERS_PATH 未设置时，传递空字符串给子进程。Playwright 会使用默认安装路径。

本地 Windows 开发需要执行:

playwright install chromium

这会将 Chromium 安装到 ~/AppData/Local/ms-playwright/（Windows 默认路径）。

注意: backend/.env.example 中有 PLAYWRIGHT_BROWSERS_PATH=/ms-playwright（Docker 路径），如果复制到 .env 且 Pydantic 加载后通过 os.environ 传递给子进程，会导致 Windows 上找不到浏览器。但目前 backend/.env 中没有此变量，所以不影响。

结论: ✓ 当前配置正确，但需要手动执行 playwright install chromium。

六、启动流程模拟

6.1 Step 1: docker compose up -d

命令: docker compose up -d（在项目根目录 c:\ui-automation\ 执行）

读取文件: c:\ui-automation\.env + docker-compose.yml

启动服务: MySQL, Redis, etcd, MinIO, Milvus, Neo4j（backend 和 frontend 服务会构建但因后端在 PyCharm 运行，不需要启动）

潜在问题:

  • 根目录 .env 中 DB_PORT=3307 + DB_HOST=mysql 冲突，但基础服务不使用此变量（只有 backend 服务使用），所以基础服务启动不受影响
  • 如果 docker compose up -d 同时启动 backend 容器，则 backend 容器会因 DB_PORT 错误而启动失败
  • 建议: 仅启动基础服务：docker compose up -d mysql redis milvus neo4j etcd minio

6.2 Step 2: 启动 FastAPI (PyCharm)

启动方式: PyCharm Run Configuration → python -m app.main 或 uvicorn app.main:app --reload

工作目录要求: c:\ui-automation\backend\（必须！）

启动流程:

  1. settings = Settings() → 从 backend/.env 加载配置
  2. init_db() → Base.metadata.create_all() → 连接 MySQL localhost:3307 ✓
  3. init_providers() → 初始化 Web/API/Performance Provider
  4. ApplicationContainer.initialize_all():
    • LLM Gateway → 初始化 Provider 链（Qwen 启用，DeepSeek/OpenAI 跳过）
    • Embedding Service → DashScope Embedding 实例
    • Vision Service → 共享 httpx 客户端
    • Marker Service → 预加载 pdfplumber / PyMuPDF
  5. Milvus 延迟初始化 → 首次使用时连接 localhost:19530
  6. TaskQueue / ExecutionQueue / Runtime v2 启动

需要额外执行:

  • alembic upgrade head — 数据库迁移（需在 backend/ 目录执行，且需设置 DB_PORT=3307 环境变量或修改 alembic.ini）
  • playwright install chromium — 安装浏览器（首次使用前执行一次）

6.3 Step 3: 启动 React (Vite)

命令: npm run dev（在 c:\ui-automation\frontend\ 目录执行）

Vite 配置: vite.config.ts → 端口 3000，/api 代理到 http://localhost:8000

需要先执行: npm install（首次）

启动风险: 无。前端配置正确，代理目标与后端端口一致。

七、问题列表

问题 1：根目录 .env 中 DB_PORT=3307 与 DB_HOST=mysql 冲突 严重

位置: c:\ui-automation\.env 第 13 行 DB_PORT=3307

影响: docker-compose.yml 的 backend 服务从 env_file 加载 DB_PORT=3307，但 MySQL 容器内部监听 3306。docker-compose 的 environment 覆盖了 DB_HOST=mysql 但未覆盖 DB_PORT，导致容器内后端连接 mysql:3307 失败。

修改建议: 将根目录 .env 中 DB_PORT=3307 改为 DB_PORT=3306（Docker 内部端口）。

问题 2：alembic.ini 硬编码 localhost:3306 严重

位置: c:\ui-automation\backend\alembic.ini 第 6 行

影响: 虽然 alembic/env.py 会覆盖此值，但 env.py 使用 os.getenv("DB_PORT", "3306")。在 PyCharm 中运行 alembic 时，.env 文件未被加载到 os.environ，默认值 3306 被使用，连接到错误的端口。

修改建议: 方案 A：在 alembic/env.py 开头添加 from dotenv import load_dotenv; load_dotenv()。方案 B：将 alembic.ini 修改为 localhost:3307。

问题 3：MILVUS_STANDALONE 未被 Pydantic Settings 加载 严重

位置: c:\ui-automation\backend\app\db\milvus_client.py 第 152 行 os.environ.get("MILVUS_STANDALONE")

影响: config.py 的 Settings 类中没有 MILVUS_STANDALONE 字段，Pydantic 以 extra="ignore" 忽略它。因此 os.environ.get("MILVUS_STANDALONE") 返回 None。当前因 MILVUS_PORT=19530 条件巧合走 Standalone 模式，但如果端口改变会意外切换到 Lite 模式。

修改建议: 在 config.py 的 Settings 类中添加 MILVUS_STANDALONE 字段，并在 milvus_client.py 中改用 settings.MILVUS_STANDALONE。

问题 4：REDIS_ENABLED=False 但 Redis 实际可用 风险

位置: c:\ui-automation\backend\.env 第 75 行 REDIS_ENABLED=False

影响: RedisExecutionQueue 在 start() 时直接尝试连接 Redis（不检查 REDIS_ENABLED），连接成功后正常工作。但 REDIS_ENABLED=False 会让开发者误以为 Redis 未启用，且其他代码可能依赖此标志做功能开关。

修改建议: 将 REDIS_ENABLED 改为 True。

问题 5：backend/.env 缺少多个必要变量 风险

位置: c:\ui-automation\backend\.env

影响: 以下变量缺失，使用 Pydantic 默认值而非显式配置：

  • SECRET_KEY — 使用默认值，开发环境可接受但不规范
  • EMBEDDING_PROVIDER — 使用默认值 dashscope（巧合正确）
  • EMBEDDING_MODEL — 使用默认值 text-embedding-v3
  • EMBEDDING_DIM — 使用默认值 1024
  • REPORT_DIR — 使用默认值 reports

修改建议: 在 backend/.env 中显式添加这些变量。

问题 4：os.getenv() 与 Pydantic Settings 混用 风险

位置: embedding/factory.py 第 13 行, milvus_client.py 第 152 行, alembic/env.py 第 26-30 行

影响: Pydantic Settings 加载 .env 后不写入 os.environ，导致 os.getenv() 调用无法读取 .env 中的值，返回默认值。当前因默认值巧合正确而未暴露问题，但属于隐患。

修改建议: 统一使用 settings.XXX 读取配置；或在 config.py 中添加 from dotenv import load_dotenv; load_dotenv() 将 .env 加载到 os.environ。

问题 5：backend/.env.example 中 PLAYWRIGHT_BROWSERS_PATH=/ms-playwright 风险

位置: c:\ui-automation\backend\.env.example 第 84 行

影响: /ms-playwright 是 Docker 内的路径，Windows 上不存在。如果开发者从 .env.example 复制到 .env，Playwright 子进程会收到错误的浏览器路径。

修改建议: 在 .env.example 中注释掉此行或标注"仅 Docker 使用"。

问题 6：MinIO 端口未映射到宿主机 提示

位置: c:\ui-automation\docker-compose.yml MinIO 服务（无 ports 配置）

影响: 无法从宿主机直接访问 MinIO Console（9001 端口）。但后端代码不直接连接 MinIO，仅 Milvus 内部使用，所以不影响功能。

修改建议: 如果需要调试 MinIO，可添加端口映射 "9001:9001"。

八、推荐 .env 结构

配置管理方案：采用双 .env 文件分离策略，根目录 .env 供 Docker Compose 使用，backend/.env 供 PyCharm 本地开发使用。两者通过 .env.example 模板保持同步。

8.1 根目录 .env（Docker Compose 专用）

负责：为 docker-compose.yml 提供环境变量，所有 HOST 使用容器名，PORT 使用容器内部端口。

# ========== Docker Compose 环境变量 ========== # 供 docker-compose.yml 使用，backend/frontend 容器通过 env_file 加载 # ---------- 应用配置 ---------- APP_NAME=Test-Automation APP_VERSION=1.0.0 USE_SQLITE=False APP_ENV=production DEBUG=False # ---------- 安全配置 ---------- SECRET_KEY=change-this-to-a-random-secret-key # ---------- MySQL（Docker 容器内部） ---------- # 容器名通信，使用内部端口 3306 DB_HOST=mysql DB_PORT=3306 # ← 修复：从 3307 改为 3306 DB_USER=root DB_PASSWORD=magic1212 DB_NAME=test_automation DB_ECHO=False # ---------- Redis（Docker 容器内部） ---------- REDIS_ENABLED=True REDIS_HOST=redis REDIS_PORT=6379 REDIS_PASSWORD= REDIS_DB=0 # ---------- Milvus（Docker 容器内部） ---------- MILVUS_HOST=milvus MILVUS_PORT=19530 MILVUS_STANDALONE=1 # ---------- Neo4j（Docker 容器内部） ---------- NEO4J_URI=bolt://neo4j:7687 NEO4J_USER=neo4j NEO4J_PASSWORD=neo4j_secure_password # ---------- AI 模型 API ---------- QWEN_API_KEY=sk-your-dashscope-api-key QWEN_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions QWEN_MODEL=qwen-vl-plus EMBEDDING_PROVIDER=dashscope EMBEDDING_MODEL=text-embedding-v3 EMBEDDING_DIM=1024 DEEPSEEK_API_KEY= DEEPSEEK_API_URL= OLLAMA_HOST=http://ollama:11434 # ---------- Playwright（Docker 内） ---------- PLAYWRIGHT_BROWSERS_PATH=/ms-playwright # ---------- 其他 ---------- LOG_LEVEL=INFO UPLOAD_DIR=uploads REPORT_DIR=reports R2R_BASE_URL=http://localhost:7272 R2R_API_KEY=

8.2 backend/.env（PyCharm 本地开发专用）

负责：为 FastAPI 后端提供本地开发环境变量，所有 HOST 使用 localhost，PORT 使用 Docker 映射到宿主机的端口。

# ========== 后端本地开发环境变量 ========== # PyCharm 启动时由 Pydantic Settings 加载 (env_file=".env") # 工作目录必须为 backend/ 目录 # ---------- 应用配置 ---------- APP_NAME=Test-Automation APP_VERSION=1.0.0 APP_ENV=development DEBUG=True HOST=0.0.0.0 PORT=8000 # ---------- 安全配置 ---------- SECRET_KEY=dev-secret-key-change-in-production # ---------- MySQL（Docker 映射端口） ---------- # Docker: 3307→3306，本地访问用 localhost:3307 USE_SQLITE=False DB_HOST=localhost DB_PORT=3307 DB_USER=root DB_PASSWORD=magic1212 DB_NAME=test_automation DB_ECHO=False # ---------- Redis（Docker 映射端口） ---------- REDIS_ENABLED=True # ← 修复：从 False 改为 True REDIS_HOST=localhost REDIS_PORT=6379 REDIS_PASSWORD= REDIS_DB=0 # ---------- Milvus（Docker 映射端口） ---------- MILVUS_HOST=localhost MILVUS_PORT=19530 MILVUS_STANDALONE=true # ---------- Neo4j（Docker 映射端口） ---------- NEO4J_URI=bolt://localhost:7687 NEO4J_USER=neo4j NEO4J_PASSWORD=neo4j_secure_password # ---------- AI 模型 API ---------- QWEN_API_KEY=sk-your-dashscope-api-key QWEN_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions QWEN_MODEL=qwen-vl-plus EMBEDDING_PROVIDER=dashscope # ← 新增 EMBEDDING_MODEL=text-embedding-v3 # ← 新增 EMBEDDING_DIM=1024 # ← 新增 DEEPSEEK_API_KEY= DEEPSEEK_API_URL= OLLAMA_HOST=http://localhost:11434 # ---------- 知识服务 ---------- KNOWLEDGE_PROVIDER=r2r R2R_BASE_URL=http://localhost:7272 R2R_API_KEY= # ---------- 日志与文件 ---------- LOG_LEVEL=INFO LOG_PATH=logs UPLOAD_DIR=uploads MAX_UPLOAD_SIZE=10485760 REPORT_DIR=reports # ← 新增 # ---------- Playwright（本地 Windows 不需要设置） ---------- # PLAYWRIGHT_BROWSERS_PATH= # 留空使用默认路径，不要设为 /ms-playwright
配置管理方案总结：
  • 根目录 .env：Docker Compose 专用，HOST 用容器名（mysql/redis/milvus/neo4j），PORT 用内部端口
  • backend/.env：PyCharm 本地开发专用，HOST 用 localhost，PORT 用 Docker 映射端口
  • .env.example：两份模板分别对应两种场景，新开发者复制即用
  • docker-compose.yml：backend 服务的 environment 段作为最终覆盖层，确保容器内配置正确
