## ④ 用户操作流程

### 流程1：接口测试 - 执行套件

```
用户点击一级菜单"接口测试"
  → 点击子菜单"执行中心"
  → 选择要执行的测试套件
  → 选择执行环境
  → 点击"立即执行"
  → 页面实时展示执行进度
  → 执行完成 → 可跳转"报告中心"查看结果
```

### 流程2：接口测试 - 查看报告

```
用户点击一级菜单"接口测试"
  → 点击子菜单"报告中心"
  → 查看历史报告列表
  → 可按日期/状态/环境筛选
  → 点击"查看" → 进入报告详情
  → 查看通过率、失败用例、响应时间等
```

### 流程3：Web测试 - 设计测试用例

```
用户点击一级菜单"Web测试"
  → 点击子菜单"测试设计"（原"创建测试"）
  → 左侧选择目标页面
  → 右侧设计测试步骤（操作+断言）
  → 点击"保存"保存用例
  → 或点击"保存并执行"直接跳转执行中心执行
```

### 流程4：Web测试 - 定时执行

```
用户点击一级菜单"Web测试"
  → 点击子菜单"定时任务"
  → 新建定时任务
  → 选择测试用例/套件
  → 设置执行周期（每天/每周/自定义Cron）
  → 保存定时任务
  → 到时间自动执行 → 结果可在"报告中心"查看
```

## ⑤ 风险说明

| 风险项 | 风险等级 | 说明 | 缓解措施 |
|--------|---------|------|---------|
| 术语变更导致用户迷失 | 中 | 老用户习惯"创建测试""执行测试""测试结果"，改为新术语后可能找不到入口 | 菜单旁增加过渡提示（如"测试设计（原创建测试）"），保留1-2个版本后移除；旧路由重定向 |
| 路由变更影响收藏/外链 | 低 | `/web-testing/create` 等旧路由被收藏或外部引用 | 所有旧路由设置 301 重定向到新路由 |
| 文件重命名影响引用 | 中 | WebCreate.tsx → WebTestDesignPage.tsx 等文件重命名，其他文件中的 import 路径需同步更新 | 全局搜索旧文件名引用，逐一更新 import 路径 |
| 接口测试与Web测试术语统一 | 低 | 两个模块都有"执行中心"和"报告中心"，用户可能混淆 | 页面标题和面包屑始终显示模块名前缀（如"接口测试 > 执行中心"） |
| 定时任务归属 | 低 | Web测试下有"定时任务"，接口测试没有，用户可能期望接口测试也有 | 后续版本考虑将定时任务提升为独立功能或统一到执行中心 |
| 术语表维护 | 低 | 后续开发可能再次使用被禁止的术语 | 建立项目术语表文档，Code Review 时检查术语合规性 |
