## ② 新路由

| 旧路由 | 新路由 | 说明 |
|--------|--------|------|
| `/requirement` | `/requirement` | 需求一级路由（不变） |
| `/requirement/list` | `/requirement/list` | 需求列表（不变） |
| `/requirement/create` | `/requirement/new` | 需求创建→新建需求 |
| `/requirement/upload` | `/requirement/upload-center` | 上传→上传中心（统一入口） |
| `/requirement/analysis` | 删除 | 独立"需求分析"页面删除，分析进入详情页 |
| `/requirement/sessions` | `/requirement/sessions` | 会话管理（不变） |
| — | `/requirement/:id` | 需求详情页（新增，含分析结果） |

### 旧路由兼容重定向

| 旧路由 | 重定向目标 |
|--------|-----------|
| `/requirement/create` | `/requirement/new` |
| `/requirement/upload` | `/requirement/upload-center` |
| `/requirement/analysis` | `/requirement/list`（独立分析页删除，跳转列表） |
| `/requirement/analysis/:id` | `/requirement/:id`（跳转对应需求详情） |

## ④ 用户操作流程

### 流程1：手动新建需求

```
用户点击一级菜单"需求"
  → 点击子菜单"新建需求"
  → 填写需求名称、描述、优先级、关联项目
  → 点击"保存草稿"或"提交并分析"
  → 若"提交并分析" → 跳转需求详情页，右侧自动展示AI分析结果
```

### 流程2：上传文件创建需求

```
用户点击一级菜单"需求"
  → 点击子菜单"上传中心"
  → 拖拽或点击上传文件
  → 系统自动识别文件类型（需求/Swagger/脚本/视频/图片/Schema）
  → 识别完成 → 自动创建对应需求
  → 用户进入"需求列表"查看新创建的需求
  → 点击需求 → 进入详情页查看分析结果
```

### 流程3：查看需求分析结果

```
用户点击一级菜单"需求"
  → 点击子菜单"需求列表"
  → 找到目标需求 → 点击"查看"
  → 进入需求详情页
  → 左侧查看需求基本信息
  → 右侧查看AI分析结果（功能点、建议用例等）
  → 可点击"一键生成用例"将分析结果转为测试用例
```

### 流程4：对未分析需求执行AI分析

```
用户点击一级菜单"需求"
  → 点击子菜单"AI分析"
  → 选择待分析的需求
  → 选择分析模式
  → 点击"开始分析"
  → 分析完成 → 点击需求进入详情页查看结果
```

### 流程5：从其他页面上传文件（统一跳转）

```
用户在任意需求相关页面看到上传按钮
  → 点击上传按钮
  → 跳转到"上传中心"页面
  → 在上传中心完成上传操作
  → 上传完成后可返回原页面
```

## ⑤ 风险说明

| 风险项 | 风险等级 | 说明 | 缓解措施 |
|--------|---------|------|---------|
| 独立"需求分析"页面删除 | 高 | 原有独立分析页面的用户可能找不到分析入口 | 旧路由 `/requirement/analysis` 重定向到 `/requirement/list`；在需求列表中"待分析"状态的需求增加醒目的"分析"按钮 |
| 上传按钮删除影响操作习惯 | 中 | 用户习惯在需求列表/详情页直接上传，改为跳转上传中心增加操作步骤 | 各页面的上传按钮改为"前往上传中心"链接，点击后新标签页打开上传中心；上传中心完成后提供返回引导 |
| 文件类型自动识别准确率 | 中 | 上传中心依赖自动识别文件类型，识别错误会导致需求创建错误 | 提供手动修正类型的功能；上传后展示识别结果，用户可修改；对无法识别的文件提示用户手动选择 |
| 需求详情页布局复杂度 | 中 | 左需求+右分析结果的布局在小屏幕下可能显示不佳 | 响应式设计：小屏幕下改为上下布局（需求在上，分析结果在下）；提供折叠/展开功能 |
| "需求创建"→"新建需求"术语变更 | 低 | 旧术语"需求创建"可能出现在文档/培训材料中 | 旧路由重定向；更新用户文档和帮助说明 |
| 上传中心与全局上传中心冲突 | 低 | 若项目已有全局上传中心（/upload-tasks），需求模块的上传中心可能造成混淆 | 明确需求上传中心是全局上传中心的子集/入口；考虑统一到全局上传中心，需求模块仅提供跳转链接 |
