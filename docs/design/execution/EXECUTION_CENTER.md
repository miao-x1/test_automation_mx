## ② 新路由

### 新增路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/execution` | ExecutionCenterPage | 执行中心主页 |
| `/execution/recent` | ExecutionCenterPage（默认Tab） | 最近执行 |
| `/execution/api` | ExecutionCenterPage（接口执行Tab） | 接口执行 |
| `/execution/web` | ExecutionCenterPage（Web执行Tab） | Web执行 |
| `/execution/schedule` | ExecutionCenterPage（定时任务Tab） | 定时任务 |
| `/execution/reports` | ExecutionCenterPage（测试报告Tab） | 测试报告 |

### 旧路由跳转映射

| 旧路由（原模块内） | 跳转目标 | 说明 |
|-------------------|---------|------|
| `/api-testing/execute` | `/execution/api` | 接口测试执行→执行中心接口执行Tab |
| `/api-testing/execution-center` | `/execution/api` | 同上 |
| `/web-testing/execute` | `/execution/web` | Web测试执行→执行中心Web执行Tab |
| `/web-testing/execution-center` | `/execution/web` | 同上 |
| `/web-testing/schedule` | `/execution/schedule` | Web定时任务→执行中心定时任务Tab |

**注意：** 接口测试和Web测试模块菜单中的"执行中心"子菜单保留，但点击后跳转到统一执行中心对应Tab，而非模块内独立页面。

## ④ 用户操作流程

### 流程1：查看最近执行

```
用户点击一级菜单"执行中心"
  → 默认进入"最近执行"Tab
  → 查看今日执行统计（执行数/通过率/失败数/执行中）
  → 下方查看快捷入口卡片（接口执行/Web执行/定时任务/测试报告）
  → 下方查看最近执行记录列表
  → 点击某条记录"详情" → 弹出执行详情抽屉
```

### 流程2：执行接口测试

```
用户点击一级菜单"执行中心"
  → 点击"接口执行"Tab（或点击快捷入口"接口执行"）
  → 选择测试套件
  → 选择执行环境
  → 点击"立即执行"
  → 列表中实时更新执行状态
  → 执行完成 → 可在"测试报告"Tab查看报告
```

### 流程3：执行Web测试

```
用户点击一级菜单"执行中心"
  → 点击"Web执行"Tab（或点击快捷入口"Web执行"）
  → 选择测试用例
  → 选择执行环境和浏览器
  → 点击"立即执行"
  → 列表中实时更新执行状态
  → 执行完成 → 可在"测试报告"Tab查看报告
```

### 流程4：从模块内跳转到执行中心

```
用户在"接口测试"模块点击子菜单"执行中心"
  → 自动跳转到 /execution/api（统一执行中心的接口执行Tab）
  → 页面展示接口执行界面

用户在"Web测试"模块点击子菜单"执行中心"
  → 自动跳转到 /execution/web（统一执行中心的Web执行Tab）
  → 页面展示Web执行界面
```

### 流程5：管理定时任务

```
用户点击一级菜单"执行中心"
  → 点击"定时任务"Tab
  → 查看所有定时任务列表
  → 点击"新建定时任务" → 填写任务名称、选择用例/套件、设置周期
  → 保存 → 任务出现在列表中
  → 可启用/暂停/删除定时任务
  → 定时执行的结果在"测试报告"Tab查看
```

## ⑤ 风险说明

| 风险项 | 风险等级 | 说明 | 缓解措施 |
|--------|---------|------|---------|
| 执行中心与模块内执行功能重复 | 高 | 接口测试/Web测试模块内原有执行页面，统一执行中心后存在两套入口 | 模块内"执行中心"子菜单改为跳转链接，指向 `/execution/api` 或 `/execution/web`；模块内不再保留独立执行页面 |
| 新建页面开发量 | 中 | ExecutionCenterPage.tsx 为全新页面，需5个Tab组件 | 优先开发"最近执行"Tab和快捷入口，复用现有接口/Web执行组件；其他Tab逐步迁移 |
| Tab状态与URL同步 | 中 | Tab切换需同步URL，用户刷新页面后应保持当前Tab | 使用 URL query 或 path segment 标识当前Tab（如 `/execution?tab=api` 或 `/execution/api`）；Tab切换时更新URL |
| 定时任务迁移 | 中 | 原Web测试下的定时任务需迁移到执行中心 | 旧路由 `/web-testing/schedule` 重定向到 `/execution/schedule`；定时任务数据不变，仅入口变更 |
| 执行记录跨模块展示 | 低 | 最近执行Tab需聚合接口/Web/定时三种类型的记录 | 后端API需支持跨类型查询；前端按时间倒序展示，类型字段区分来源 |
| 测试报告聚合 | 低 | 原接口测试报告和Web测试报告格式可能不同 | 报告Tab内按类型分组展示；点击查看跳转各自报告详情页 |
